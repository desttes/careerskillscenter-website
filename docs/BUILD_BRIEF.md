## 0. Read this first — rules for the builder

1. **Follow the repo's existing build system (see `PROJECT-HANDOFF.md`, `README.md`, `docs/SITE-STRUCTURE.md`, `docs/PAGES.md`).** Inner pages are GENERATED by `tools/build-pages.py`. Never hand-edit a generated inner page:
   - Shared header / nav / footer / contact dialog → edit in `index.html`, then run `python3 tools/build-pages.py`.
   - Each new page → add a `PAGES.append(dict(...))` block in `tools/build-pages.py`.
   - `sitemap.xml` and cache-busting are auto-generated by the build. GA4 (`G-0XDE7E7RGQ`) is already on every page.
   - No new frameworks or build tools without asking.
2. **Match the existing design.** Reuse the design tokens in `css/style.css` (navy `#003B69`, yellow `#FAB814`, etc.), existing section patterns, and `js/main.js`. Do not introduce a new design system.
2b. **Forms need a backend first.** Per `PROJECT-HANDOFF.md` §6, the contact form is a demo and sends nothing. `qualify.html`, the employer forms and the checklist download all depend on a working form backend. Before building them, propose an option (e.g., Formspree, or a cPanel PHP mailer on the Namecheap host) and ask Emilio to choose. Every form must post a hidden `source` field.
2c. **Do not deploy without approval.** Build and preview locally (`python3 -m http.server 8123`), commit to git as a restore point, and list what's ready in `docs/BUILD_STATUS.md`. Deploy over SFTP (handoff §5) only when Emilio says so.
3. **Compliance guardrails (must follow):**
   - **Do NOT write "WIOA-funded," "free with a grant," "ETPL-approved," or "state-approved training provider"** for B2C programs. The school is not on the ETPL yet. Use the feature flag in §6.
   - **Do NOT write "listed in the Express Course Directory" or "approved Express provider"** until Emilio confirms it. Use the feature flag in §6.
   - Mark every funding number (caps, percentages, timelines) as a config value, never hard-coded in copy. The values in §6 carry `VERIFY` tags and must be confirmed with CommCorp (express@commcorp.org) before launch.
   - Never promise a student or employer that they will be approved for funding. Use "may qualify," "we'll help you check."
4. **Every new page needs:** unique `<title>` and meta description (given below), one H1, a primary CTA, the shared nav and footer, mobile-responsive layout, and alt text on images.
5. **Blog posts are drafts.** Write them to the spec in §5, clearly marked `DRAFT – facts to verify` at the top in an HTML comment, and list the claims that need verification. Emilio publishes after review.
6. **When done, update `docs/BUILD_STATUS.md`** (create it) with: pages built, URLs, open TODOs, and any decision you made that differs from this brief.

### 3.2 See If You Qualify — `qualify.html` (NEW, lead magnet #1)
A 60-second, 5–6 step form. **It captures a lead; it does not make an eligibility decision.**
- **Title:** See If You Qualify for Funded Career Training in Massachusetts
- **H1:** See if you qualify in 60 seconds
- **Questions (one per screen, progress bar):**
  1. Which program interests you? (Medical Billing & Coding / IT Support / Skilled Trades / Not sure)
  2. Do you live in Massachusetts? (Yes / No)
  3. What's your current work situation? (Unemployed / Laid off in the last 2 years / Working part-time or low wage / Working full-time / Other)
  4. Do you or your household receive SNAP, TAFDC, SSI or other public assistance? (Yes / No / Prefer not to say)
  5. Would your employer pay for training? (Yes / Maybe / No / Not working)
  6. Contact: first name, mobile phone, email, preferred language (English / Español / Português), consent checkbox for SMS.
- **Result screen (soft routing, never a yes/no verdict):**
  - Q2 = Yes AND Q3 in {Unemployed, Laid off, Part-time/low wage} OR Q4 = Yes → "You may be a good fit for state-funded training. An advisor will text you within 1 business day." (If `FUNDING_ETPL_APPROVED=false`, add: "We'll also show you options to start now.")
  - Q5 in {Yes, Maybe} → add a line + link: "Your employer may be reimbursed by Massachusetts" → employers.html
  - Otherwise → "Let's find the best way for you to pay. An advisor will text you within 1 business day." + link to Ways to Pay.
- **Submission:** Post to the existing contact-form handler with a hidden field `source=qualify` and all answers. If the handler can't take extra fields, flag a TODO.
- Plain-language, mobile-first, big buttons. Add Spanish and Portuguese versions later (TODO).

### 4.4 Reimbursement Calculator — `reimbursement-calculator.html` (lead magnet #2)
Client-side JavaScript; no backend. **All caps and rates come from the config in §6.**
- **Inputs:** number of employees attending · course hours · price per seat · number of MA employees at the company (drives the rate tier) · amount already used this calendar year (optional, default 0).
- **Logic:**
  ```
  total_cost        = seats * price_per_seat
  cap_by_hours      = course_hours * EXPRESS_MAX_PER_INSTRUCTIONAL_HOUR
  cap_by_person     = seats * EXPRESS_MAX_PER_PERSON_PER_COURSE
  eligible_cost     = min(total_cost, cap_by_hours, cap_by_person)
  rate              = (ma_employees <= EXPRESS_SMALL_EMPLOYER_MAX) ? EXPRESS_RATE_SMALL : EXPRESS_RATE_LARGE
  estimate          = eligible_cost * rate
  remaining_annual  = max(0, EXPRESS_ANNUAL_CAP_PER_COMPANY - already_used)
  estimate          = min(estimate, remaining_annual)
  your_cost         = total_cost - estimate
  ```
- **Output:** "Estimated reimbursement: $X · Your estimated cost: $Y," plus the disclaimer: "Estimate only. Final amounts are set by Commonwealth Corporation. Rates and caps are subject to change." CTA → employer form.
- Include unit tests for the function if the repo has any test setup; otherwise add a small test page `calculator-test.html` with 4 known cases (TODO: Emilio confirms expected values).
